# Безопасное обновление — версия 17 ORACLE

Эта версия меняет хранение, механизм обновления и оформление ORACLE. Состав троек исправлен: Печерских / Репин / Осинкин и Сурнин / Торопов / Сабуров. Ручные назначения на отгрузку корректно входят в общее число. Очередь локаций учитывает дату последней поездки; поездка вчера или сегодня отодвигает человека, пока есть другие доступные. Небольшое преимущество после отпуска действует до выравнивания числа поездок. При нехватке разных сотрудников один человек может выехать на разные локации в тот же день; каждая поездка записывается.

## Первый переход со старой версии 13

1. На каждом рабочем телефоне офлайн открыть Настройки → Экспорт и сохранить JSON вне данных сайта.
2. Открыть прежний адрес в прежнем браузере с интернетом. Дождаться скачивания ресурсов; полностью закрыть все окна программы и снова открыть.
3. Проверить надпись «Версия 17-ORACLE», журналы, счётчики и настройки. Проверить открытие без интернета.

Старая версия не содержит интерфейса обновления. Добавить уведомление в уже скачанный старый JavaScript без загрузки новой версии невозможно. Новый service worker не вызывает skipWaiting при установке, поэтому первый переход произойдёт после закрытия старых окон. До нормализации данных ORACLE сохраняет исходную строку dutyApp в отдельный ключ.

## Последующие обновления

При открытой программе онлайн или возвращении сети проверяется service worker. После загрузки ресурсов появляется предложение скачать JSON. Пользователь подтверждает сохранение файла кнопкой установки. Браузер не позволяет достоверно проверить, что пользователь сохранил файл в загрузки, поэтому подтверждение ручное. Перед активацией проверяется актуальность копии и создаётся локальная резервная копия. Несколько открытых окон блокируют активацию по кнопке. Если все окна закрыты, браузер может активировать ожидающий worker автоматически; следующий запуск обязан выполнять резервирование до миграций.

История не удаляется и не импортируется обратно автоматически. Используется прежний ключ dutyApp и прежний origin. Импорт и полный сброс также сохраняют резервную копию. Локальные копии можно увидеть в настройках и восстановить после явного подтверждения; текущее состояние перед заменой также сохраняется. При ошибке чтения, квоте или устаревшем состоянии окна показ блокируется, сохранение останавливается. Recovery JSON содержит исходные строки и предназначен для диагностики, а обычный backup JSON подходит для существующего импорта.

Не менять адрес сайта/браузер, не очищать данные и не переустанавливать приложение. Локальные копии не спасают от очистки данных браузера или потери телефона; для этого нужен внешний JSON.

Для следующего выпуска менять CACHE_NAME и DutyStorage.VERSION, включать все ресурсы в FILES. Старые кеши пока сохраняются: автоматической очистки чужих приложений больше нет. Ограничение: проверка устаревшего состояния уменьшает риск конфликтов вкладок, но localStorage не предоставляет полноценные транзакции между вкладками. Работать следует в одном окне.

## Проверка

node --test tests/*.cjs

Проверены сохранение старых журналов и настроек, повторный запуск, повреждённый JSON, переполнение хранилища, устаревшая вкладка, неверный импорт, активация worker и офлайн-ответы. Проверка реального обновления на Android с пользовательским экспортом ещё требуется до рабочего выпуска.
